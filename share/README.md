# 论文判读实践 · 技术分享索引

这里是我用同一套判读方法处理两篇论文的完整实践记录。两篇都是**围绕一个具体阅读问题**做的真实判读，不是论文推荐，也不是摘要翻译。

方法出处：[`science-explainer`](../README.md) 的 audit 判读模式（MIT）。核心约束是三条：**每条结论带原文锚点与引文**、**区分原文事实（F）/ 推断（I）/ 论文未报告（U）**、**能用论文数字算的必须算到底并写出算式**。

## 两篇分享

### 一、MoG-VLM 判读：一个视频异常检测模型能否用在边缘设备上

**阅读问题**：这套方法能不能用在「16 路摄像头 + 单张 RTX 4090 24GB + 端到端告警延迟 < 2 秒 + 关注打架/入侵/摔倒」的园区监控上？

**论文**：Dawoud K W, Zaheer M Z, Muhammad K, Khan M H. *MoG-VLM: Efficient Video Anomaly Detection through Motion-Guided Vision-Language Models*. arXiv:2610.31478v1, 2026.

**[→ 读这篇](mog-vlm/README.md)**

这篇解决的是**论文缺数据**的问题：论文只在 A100 上测过单流，我的目标是 4090 上跑 16 路并要在线延迟。所以主要工作是从论文已给的数字做量纲外推。

| 结论 | 算式 |
|---|---|
| 显存装不下 | 19B × 2 字节 = 38 GB ÷ 24 GB = **1.58 倍** |
| 延迟超标 | 五段相加 = **2.38 s**，超 2 s 预算 19% |
| 吞吐高峰态吃紧 | 16 路 × 3 FPS = 48 ÷ 43.84 = **1.10 倍** |

四个「普通读法读不出来」的发现：

- 43.84 FPS 靠**只让 6.7% 的帧真正进 VLM**（由 Table 3 反推）——门控越灵敏，这个瓶颈越早到
- 时序模型规格**两处自相矛盾**：§4.2 写 `VideoLLaMA3-7B`，附录 C.3 写 `Video-LLaMA 8B`
- 提示词引用编号**错位**：正文写 `C.3.1/C.3.2/C.3.3`，附录实际只有 `C.1/C.2/C.3`
- UCF 吞吐**正文与表格不一致**：36.25 vs 39.25

### 二、日本沼虾骨架化表型论文判读：能不能当我课题的对比基线

**阅读问题**：一篇报「弯曲误差削减 70.3%」的论文，能不能作为「水下双目 + 仅侧视 + 活体不可标记 + 多群体」课题的对比基线？

**论文**：Du X, Qu J, Yin B. *Non-Contact Phenotypic Measurement and Body Mass Prediction of Penaeus japonicus Based on Skeletonization and Multi-View Comparison*. Sensors 2026, 26, 4892. DOI [10.3390/s26154892](https://doi.org/10.3390/s26154892)（**CC BY 4.0**）

**[→ 读这篇](peneaus-japonicus/README.md)**

这篇解决的是**论文有数据但口径不全**的问题：论文报了分组指标，但没报加权总体值；报了相对提升，但没做统计检验；写了「水产养殖」，但实际是干燥台面实验。

| 结论 | 算式 |
|---|---|
| 70.3% 是局部值 | 只对重度组 40 例（13.3%）成立 |
| 整体只有 32.4% | (3.847 − 2.602) ÷ 3.847 = **32.4%** |
| 尺度误差容忍窗口极窄 | 超过 **1.245 pp** 净收益即归零 |

三个决定性的发现：

- **这不是水下实验**：`underwater` 全文 3 次命中，全部在参考文献标题里；实际是手机架高 40 cm 在白色哑光纸上俯拍
- **轻度弯曲组（48.7% 样本）里所提方法排第三**：MAE 0.365 vs 直线 0.357、MBR 0.359；论文表述为「四种方法相对接近」
- **核心对比零统计检验**：§3.3（长度，即主要贡献）p 值 0 处、CI 0 处、Holm 0 处；而 §3.4/§3.5 有完整的 bootstrap CI + Holm 校正

## 两篇的对照：同一套方法，两种用法

| | 第一篇 MoG-VLM | 第二篇 日本沼虾 |
|---|---|---|
| 论文性质 | 新预印本，工程导向 | 正式发表，方法导向 |
| 主要缺口 | 论文没测目标条件 | 论文条件不同但未说明程度 |
| 关键产出 | 「差 1.58 倍」（论文无数据） | 「32.4% 而非 70.3%」（论文有数据未加权） |
| 方法最起作用处 | 定量外推 | 分组加权还原 + 检验密度对比 |
| 适用形态 | 论文**缺数据**时，靠外推补出可决策判断 | 论文**口径不全**时，靠重算还原整体 |

**这个方法验证的是「引用是否忠实」，不是「论文是否正确」。** 两者都重要，但不是一回事——没有原始数据，就无法验证作者的原始计算。

## 复现

两篇分享的每一步都可以重跑，材料随包提供，**无需联网**。

```bash
# 生成段落索引（锚点唯一来源）
python skill/scripts/extract_paper.py <论文.txt> --out-json index.json

# 定位引文（处理 PDF 双栏换行导致的匹配失败）
python skill/scripts/locate_quote.py <论文.txt> "原文片段"

# 结构自检
python skill/scripts/check_article.py <判读输出.md> --mode audit
```

**一个必须知道的限制**：`check_article.py` 只查结构（有没有锚点、有没有标 F/I/U、有没有算式），**不查锚点指向的位置是否正确**。第二篇判读初稿有 8 条锚点的字符终点填错，自检仍报 ALL PASS——真正的纠偏来自把锚点切片回原文逐条比对（`total=25 bad=0`）。

## 材料构成

正文里引用的路径分两类，请注意它们的所在位置不同：

| 目录 | 内容 | 位置 |
|---|---|---|
| `share/` | 两篇分享正文（入口即本页） | 本仓库 + 材料包 |
| `skill/` | `science-explainer` v0.2.1 源码 | 本仓库 + 材料包 |
| `runs/<案例>/` | 判读输出与执行过程记录（含纠错日志） | **仅材料包** |
| `cases/<案例>/` | 任务定义与验收标准（运行前写定） | **仅材料包** |
| `materials/<案例>/` | 论文原件、提取文本、段落索引 | **仅材料包** |

`runs/`、`cases/`、`materials/` 三类是运行产物与论文原件，体积与版权原因不入库，随比赛材料包提供。两篇的目录名分别为 `mog-vlm` 与 `peneaus-japonicus`——正文里写的 `runs/mog-vlm/A-with/output.md` 等路径，指的就是材料包内的这一层。
