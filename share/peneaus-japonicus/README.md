> 第二次判读实践。这次不是为了判断「能不能用」，而是为了回答一个更具体的问题：**这篇论文能不能当作我自己课题的对比基线？**

**论文**：Non-Contact Phenotypic Measurement and Body Mass Prediction of *Penaeus japonicus* Based on Skeletonization and Multi-View Comparison
**作者**：Xuanyu Du, Junpeng Qu, Baoquan Yin（烟台研究院 / 中国农业大学）
**来源**：*Sensors* 2026, 26, 4892；DOI [10.3390/s26154892](https://doi.org/10.3390/s26154892)；**CC BY 4.0**（可合法全文分享）

**我的场景**：水下双目立体视觉 + 多关键点形态特征的日本沼虾体重预测课题（仅侧视 / 封装双目入水 / 活体不可标记 / 多产地群体）

## 0. 结论先说

**这篇论文的某一句话可以直接引用，但它的核心数字不能当整体收益引用。**

先说可以引用的部分，这部分做得很扎实：**「在弯曲姿态下，骨架弧长优于直线距离」这个方向性结论成立**。重度弯曲组里骨架法 MAE 0.399 cm，直线法 1.345 cm，三种指标（MAE/MAPE/RMSE）方向一致，且与 Zhang–Suen 基线对比也成立。作为方法学依据，站得住。

再说不能直接引用的部分。这是我这次判读最主要的产出：

| 问题 | 论文表述 | 我算出的事实 |
|---|---|---|
| 「削减 70.3%」的适用范围 | 摘要头条位置（MAE 口径） | 仅对**重度弯曲组 40 例（13.3% 样本）**成立 |
| 整体能拿到多少 | **论文未报加权总体值** | 同 MAE 口径加权：**34.1%**；MAPE 口径：**32.4%** |
| 轻度弯曲组表现 | 「四种方法相对接近」 | 骨架法**排第三**：MAE 0.365 > 直线 0.357 > MBR 0.359 |
| 长度对比的统计检验 | — | **完全没有**：p 值 0 处、置信区间 0 处、校正 0 处 |
| 成像介质 | 论文通篇讲「水产养殖」 | **干燥台面 + 手机俯拍**，`underwater` 全文只出现在参考文献标题里 |
| 参考真值 | 「independently acquired manual reference」 | **人工两段式弦长**，不是真弧长 |

最后两行是决定性的。它们意味着：**这篇论文不是水下实验，也不是用真弧长做真值。** 而这两点恰好是我课题的两个核心变量。

**最关键的定量判断**（详见第 3 节）：我的水下尺度误差只要超过 **1.25 个百分点**，就会吃掉骨架法在整组上的全部收益。而平板端口引起的水下主距漂移量级是 1%–25%——**同一个数量级**。

## 2. 方法：为什么这次要比上一篇更严格

上一篇（MoG-VLM 判读）我用的也是同一套方法：锚点强制 + F/I/U 三级标注 + 定量外推。这次加了三条更硬的要求，原因是**这次判读的结论要写进我自己的论文，错误成本更高**。

### 2.1 三条新增要求

**第一，区分「分组最优」与「整体最优」。**
论文按弯曲程度分了三组，报的是分组指标。**分组指标不能直接外推为整体指标**——这看起来是常识，但摘要里只放了一组数字时，读者极易把它当成总体结论。我这次强制自己做了加权还原。

**第二，检查对照比较的统计检验是否存在。**
相对提升百分比（「降低 70.3%」）是**点估计**，没有置信区间就无法判断这个差异是否超出噪声。所以我要逐节统计 p 值、CI、多重比较校正的出现次数。

**第三，把「论文没做的那一项」换算成我的场景里的门槛。**
这是最关键的一条。论文没考虑水下尺度误差，但我的场景里它必然存在。光说「论文没考虑」没有用，必须算出「这个误差大到多少，论文的结论就失效」。

### 2.2 具体做法

五段判读契约（方法卡片 → 证据表 → 支持度判定 → 定量外推 → 局限与边界 → 后续方向），每条结论标 `F`（原文事实）/ `I`（我的推断）/ `U`（论文未报告）。

工具是 [`science-explainer`](https://github.com/2025247378/science-explainer) 的 audit 模式（MIT，v0.2.1），配三个脚本：`extract_paper.py`（生成字符位置索引）、`locate_quote.py`（处理 PDF 断行定位）、`check_article.py`（结构自检）。

**这次的一个技术前提值得说明**：论文 PDF 是双栏排版，直接用字符串查找会在换行处失败。比如 `Forty-seven samples were excluded` 这句，在提取文本里被换行切开了。所以我所有引文都用 `locate_quote.py` 做「去空白匹配」定位，而不是直接 `find()`。

## 3. 四个普通读法读不出来的发现

### 发现一：70.3% 是局部数字，整体只有 32.4%（同口径 34.1%）

这是本次判读最重要的发现。论文报了分组 MAPE，但**没有报按样本数加权的总体值**。我把它还原出来：

三组样本数是 146（轻度）/ 114（中度）/ 40（重度），合计 300。加权计算：

```
直线法：
  146 × 2.520% = 367.92
  114 × 3.702% = 422.03
   40 × 9.103% = 364.12
  合计 1154.07 ÷ 300 = 3.847%

骨架法：
  146 × 2.594% = 378.72
  114 × 2.559% = 291.73
   40 × 2.755% = 110.20
  合计 780.65 ÷ 300 = 2.602%
```

整体降幅：

```
(3.847% − 2.602%) ÷ 3.847% = 32.4%
```

**这里有一个我自己写错过、必须点明的口径问题。** 论文摘要的 70.3% 是 **MAE** 口径（1.345 cm → 0.399 cm），而上面算出的 32.4% 是 **MAPE** 口径。两个不同指标不能直接相减或相除。为做同口径比较，我把 MAE 也按样本数还原了一遍：

```
直线法 MAE 整体：(146×0.357 + 114×0.546 + 40×1.345) ÷ 300 = 0.5606 cm
骨架法 MAE 整体：(146×0.365 + 114×0.365 + 40×0.399) ÷ 300 = 0.3695 cm
MAE 口径整体降幅：(0.5606 − 0.3695) ÷ 0.5606 = 34.1%
```

所以正确的说法是：**同一 MAE 口径下，重度组削减 70.3%，整体削减 34.1%**；换成 MAPE 口径，整体是 32.4%（两种口径的整体值接近但不等，因为 MAE 与 MAPE 的分母不同）。原先把 70.3% 与 32.4% 直接对比是我第一版正文的错误，已改正——这恰好也说明为什么「报告一个百分比必须连口径一起报」。

差距的来源很清楚：重度组只有 40 例，占 13.3%；而轻度组 146 例（48.7%）里骨架法并不占优。

| 弯曲组 | 样本数 | 占比 | 骨架法相对直线法（MAPE） |
|---|---:|---:|---|
| 轻度（CI≤1.08） | 146 | 48.7% | **更差**（2.594 vs 2.520） |
| 中度（1.08<CI≤1.15） | 114 | 38.0% | 更好（2.559 vs 3.702） |
| 重度（CI>1.15） | 40 | 13.3% | 大幅更好（2.755 vs 9.103） |

**这不是说论文错了。** 分组报告本身是诚实的，摘要里也明确写了「for severely curved prawns」。问题在于：**当这个数字被转引时，「for severely curved prawns」这个限定语是最容易掉的**，而且「70.3%」通常也不会带上「MAE 口径」这个标签。我在自己的课题文档里就写过「骨架化修正可削减约 70% 的弯曲误差」——对照这次判读，这句话在口径与适用范围上都缺限定。

**级别**：`I`（我的计算）。分组 MAE / MAPE 是 `F`（Table 2 原文），加权方式是我的选择。两种口径的完整复算见 `tools/verify_weighted_mape.py` 的第 [4] / [4b] 段。

### 发现二：轻度弯曲组里，所提方法排第三

Table 2 的轻度组一行：

```
              Straight-Line   MBR    Zhang-Suen   Skeleton-Based
MAE/cm            0.357       0.359     0.380          0.365
MAPE/%            2.520       2.550     2.660          2.594
RMSE/cm           0.469       0.474     0.450          0.467
```

骨架法在 MAE 和 MAPE 上都**劣于**它要击败的直线法和 MBR 法，RMSE 也只排第三。三项指标方向一致。

论文对此的表述是：「In the mildly curved group, the MAE values of all four methods were relatively similar.」（轻度组四种方法的 MAE 相对接近。）

这句话**在事实层面没有错**——0.357 到 0.380 确实很接近。但它没有点明一个读者应该知道的事：**在这个占近一半样本的组里，所提方法不是最好的**。

**为什么这不构成方法缺陷**：轻度弯曲时（CI≤1.08），骨架路径与直线距离本来差异就小，额外的骨架化步骤引入的噪声反而占了主导。这是**可预期的**，不是 bug。它真正的含义是：**骨架法有适用区间，在轻度弯曲时应退回直线法**——而论文没有给出这个切换判据。

**级别**：`F`（Table 2 数据）+ `I`（「应设切换判据」是我的建议）。

### 发现三：核心对比没有统计检验，而次要分析有

这条是我在逐节统计时发现的，对比很刺眼：

| 章节 | 内容 | p 值 | 置信区间 | Holm 校正 |
|---|---|---:|---:|---:|
| §3.3 | **长度测量方法比较（核心贡献）** | **0** | **0** | **0** |
| §3.4 | 体重预测模型比较 | 3 | 2 | 1 |
| §3.5 | 统一模型配对比较 | 2 | 3 | 2 |

**论文的主要贡献（骨架法优于三种基线）全部是点估计，没有任何统计检验。**

而次要部分做得相当规范：独立测试集带 bootstrap 95% 置信区间、RF 与其他四模型的配对比较做了 Holm 校正、还补了 200 次重复的样本量配平消融。

这个落差说明：**作者知道该怎么做检验，只是没把检验用在核心对比上。** 40 例的小样本、三组分层、四种方法的多重比较——这三个因素叠加，恰恰是最需要校正的场景。

**我不能据此说「结论不可靠」**（我算不了他们的配对差值）。但我可以说：**这个方向性结论目前只有点估计支持，引用时应表述为「数值上更低」，而不是「显著更低」。** 而 §3.4/§3.5 那部分则可以放心引用其检验结论。

**级别**：`F`（检验缺失是原文事实）。

### 发现四：这不是水下实验

这条对别人可能无所谓，对我则是决定性的。

论文写「aquaculture」「prawn phenotyping」，读起来像是养殖场景。但实际成像条件是：

| 项 | 原文 |
|---|---|
| 环境 | **controlled laboratory conditions**（受控实验室条件） |
| 设备 | Redmi K60 手机，架高约 **40 cm 垂直向下**拍摄 |
| 背景 | **白色哑光背景纸**铺在成像面上 |
| 姿态 | 每尾虾**自然放置**在白纸上 |
| 是否入水 | **否** |

我全文检索了 `underwater`：**3 次命中，全部在参考文献标题里**（引用的别人论文）。方法、实验、讨论部分一次都没出现。

**含义**：空气中的成像误差主要是分割边界误差（像素级、近似随机）；水下的成像误差多了一项**尺度误差**（折射导致，系统性、同比例影响所有长度）。这两类误差对「方法 A 比方法 B 好多少」这个差值的影响方式完全不同——尺度误差会同时抬高两者，但也可能改变差值。

所以：**「骨架法在空气中整体优于直线法 32.4%（MAPE 口径）」不能推出「在水下也优于 32.4%」。**

## 4. 定量外推：把「不一致」算成门槛

上一节说清了不一致在哪。这一节回答：**不一致到什么程度，结论就失效？**

### 4.1 水下尺度误差的容忍窗口

骨架法的整体 MAPE 是 2.602%。我的场景多一项尺度误差 `ε`，则：

```
我的 MAPE ≈ 2.602% + ε
```

令它等于各对照法的加权基线，解出平衡点：

| 对标对象 | 平衡式 | 允许的 ε |
|---|---|---|
| vs 直线法（3.847%） | `2.602 + ε = 3.847` | **1.245 pp** |
| vs MBR 法（3.500%） | `2.602 + ε = 3.500` | **0.898 pp** |
| vs Zhang–Suen 基线（2.840%） | `2.602 + ε = 2.840` | **0.238 pp** |

**结论**：尺度误差超过 **1.25 个百分点**，骨架法相对直线法的净优势归零。相对 Zhang–Suen 基线，门槛低到 **0.24 pp**。

而我这篇论文要处理的折射校正问题，平板端口引起的水下主距漂移量级是 **1%–25%**（引自课题技术侦察报告对 Shortis 的转述，不是本文数据）。漂移百分比与尺度误差百分比同量级但不是同一个量，严格换算需要我自己的标定残差。

**但量级已经足够说明问题：这个容忍窗口（1.25 pp）与已知漂移量级（1%–25%）落在同一区间。**

**最重要的推论**：如果我不管标定就直接上骨架法，很可能得到一个**比直线法更差**的结果，而且我会误以为是骨架算法的问题，去找算法的错——**实际错在标定**。这就是「不加限定的引用」最实际的风险。

### 4.2 剪枝阈值：一个不能照抄的硬编码参数

论文的骨架剪枝阈值是 **15 像素**（用于去除额剑、步足、尾扇产生的短枝）。

这是**像素量**，不是物理量。它对应多少毫米，取决于：

```
该文：40 cm 工作距离 + 3472×4624 分辨率 → 15 px ≙ ? mm
我的：工作距离与分辨率若不同 → 15 px ≙ 另一个 mm
```

论文没有给 cm/px 换算，所以「15 像素对应多少毫米」**无法从本文外推**（`U`）。可以确定的只是：**这个参数不可移植**。

这是复现型论文里最容易被忽略的一类坑——算法框架可以照搬，但这些藏在方法章节里的硬编码数值必须按自己的成像几何重标定。

### 4.3 18.7% 的样本被剔除了

```
347 例（原始）
  ↓ 剔除 47 例（CI 无法可靠计算：掩码边界不完整 / 骨架分支异常）   −13.5%
300 例
  ↓ 再剔 18 例（视角不明 / 无有效称重）                          −6.0%
282 例
```

**累计损耗 18.7%。**

关键在于**剔除理由**：「掩码边界不完整或骨架分支异常」——这类样本更可能是高弯曲、遮挡、贴边的困难样本。也就是说，重度组的 0.399 cm 应理解为「**在能被成功骨架化的重度弯曲样本上**的误差」，而非「所有重度弯曲样本的误差」。

论文未报告被剔除 47 例的 CI 分布（`U`），所以偏差方向无法量化。但**方向性风险是明确不利的**：如果被剔除的恰好是高弯曲样本，那重度组的优势可能被高估。

对我更直接的含义：**我的水下图像质量比空气差，掩码边界不完整的比例会更高**。如果这篇论文在空气中就损耗了 13.5%，我在水下需要预期更高的失败率，而这部分成本必须提前算进实验设计。

## 5. 支持度判定

把上面所有分析合起来，逐项回答「能不能用」：

| 我要做的事 | 判定 | 依据 |
|---|---|---|
| 引用「骨架弧长优于直线距离」的方向性结论 | **强支持** | 重度组三项指标同向，与 ZS 基线对比亦成立 |
| 引用「削减 70%」作为整体收益 | **反证** | 仅对 13.3% 样本成立，整体同口径加权 34.1% |
| 引用骨架法在我的场景有净收益 | **证据不足** | 该文在空气中测得，水下尺度误差量级未知 |
| 引用绝对误差值（如 MAE 0.365 cm） | **证据不足** | 参考真值是两段弦长而非真弧长；成像几何不同 |
| 认为轻度组不占优是方法缺陷 | **不成立** | 轻度弯曲时骨架与直线差异小，噪声占主导属预期 |
| 照抄 15 像素剪枝阈值 | **证据不足** | 该值绑定 40 cm / 3472×4624，无 cm/px 换算 |
| 引用其体重预测部分的实验设计 | **强支持** | 重复五折 CV + bootstrap CI + Holm + 配平消融，可作范本 |
| 把它当「水下虾类表型」的先例 | **反证** | 它自身不是水下实验 |

**还有一处必须点明的地方**：论文的参考真值是人工「两段式」测量——在头胸甲-腹交界处断开，分两段量后相加。从几何上看，**这等于两段弦长之和，而不是真弧长**。所以「骨架法更接近两段式参考」并不等于「骨架法更接近真弧长」。论文确实做对了一件事（参考值独立于图像处理结果，避免了循环论证），但真值本身的偏差方向没有讨论（`U`）。

这不影响「骨架法优于直线法」这个**相对**结论——两者用同一个参考值比较，偏差会部分抵消。但它**绝对**影响误差数值能否直接搬用。

## 6. 这篇论文做得好、值得学的地方

判读不是找茬。这篇论文有几处做得比多数同类论文好，我直接借鉴到了自己的方案里：

**第一，样本量配平消融。** 统一模型在顶视图上看似好 1.03 pp，作者做了一次 200 次的分层下采样实验，把训练样本量配平到与专用模型一致，结果优势不复现（只在 30.5% 的重复中更优）。**然后作者主动在正文里否定了自己的数字优势。**

这在论文里很少见。多数人会把这个「看似更好」的数字留在摘要里。作者没有。

**第二，诚实标注不显著。** RF 在数值上最优（MAPE 7.249% vs PLR 8.007%），但作者明确写「None of the paired comparisons ... reached statistical significance after Holm correction」，并解释为小样本导致的检验力不足，而不是宣称 RF 显著更优。

**第三，CI 阈值在误差分析之前就定好。** 1.08 / 1.15 两个分层阈值是在误差分析**之前**确立的，避免了「事后按结果挑阈值」这个常见问题。

**第四，完整披露局限。** 独立测试集 29 例、重度组 40 例、单一产地单一设备、参考值有人工不确定性——四条全部自己写明，并给出了未来改进方向。

这四点合起来，是我愿意把这篇论文作为对比基线的原因：**它的数据可能不完全适用我的场景，但它对自己的数据是诚实的。** 引用一篇诚实的论文，风险远低于引用一篇夸大的论文。


**为什么值得额外提供一个脚本**：上面五步里，步骤 1–4 只验证「我的引用是否忠实」，步骤 5 验证「我的计算是否正确」。前者读者可以照着核对，后者原本只能相信我的算式——现在可以自己跑。<br>
`--json` 输出机器可读结果（含每个输入的字符区间与逐项断言），便于嵌进自己的检查流程；`--out` 可同时落盘到 `results/`。

手工算式（与脚本输出应逐位一致）：

```
MAPE 口径
直线法：146×2.520 + 114×3.702 + 40×9.103 = 1154.07 ÷ 300 = 3.847%
骨架法：146×2.594 + 114×2.559 + 40×2.755 =  780.65 ÷ 300 = 2.602%
降幅  ：(3.847 − 2.602) ÷ 3.847 = 32.4%

MAE 口径（与论文头条 70.3% 同口径）
直线法：146×0.357 + 114×0.546 + 40×1.345 = 168.17 ÷ 300 = 0.5606 cm
骨架法：146×0.365 + 114×0.365 + 40×0.399 = 110.86 ÷ 300 = 0.3695 cm
降幅  ：(0.5606 − 0.3695) ÷ 0.5606 = 34.1%
```

> **Windows 提示**：`--out` 用相对路径。Windows 下 Python 对 `/tmp/xxx` 的解析与 Git Bash 不一致，写绝对路径可能报文件不存在——改相对路径即可。

### 7.3 结果检查方法

| 检查项 | 预期 | 不符时的含义 |
|---|---|---|
| 步骤 1 段落数 | 144 | 段数差异来自 PDF 提取工具，不影响锚点有效性 |
| 步骤 2 定位 | 10135 / 10169 附近 | 若偏移较大，说明 txt 提取方式不同（换行处理差异） |
| 步骤 3 自检 | 7 项全 PASS | C12 FAIL 多为算式未写成 `A × B = C` 形式 |
| 步骤 4 锚点 | `bad=0` | `bad>0` 说明引文与原文不符，需逐条修 |
| 步骤 5 复算 | 12 项全 `[OK]`，退出码 0 | 出现 `DIFF` 说明原文数值与我报的不一致；出现 `[FAIL]` 多为论文版本不同或 `--txt` 路径不对 |

**关于锚点校验，这次有个实际教训**：我第一次填锚点表时，8 条记录的 `end` 值填短了（引文本身没错，是终点位置写少了）。脚本比对时 report 出 `bad=8`。修正后才 `bad=0`。

**这说明锚点校验必须真正做切片比对，不能只看自检脚本报 PASS**——`check_article.py` 只检查「有没有锚点」，不检查「锚点指向的位置对不对」。这两件事完全不同。

## 8. 两篇判读的对照：同一套方法在什么情况下最有用

上一篇判读（MoG-VLM，一个视频异常检测模型）和这一篇，用的同一套方法，但收获完全不同：

| | 第一篇（MoG-VLM） | 第二篇（本文） |
|---|---|---|
| 论文性质 | 新预印本，工程导向 | 正式发表，方法导向 |
| 主要问题 | 论文没测我的硬件条件 | 论文的条件与我的不同，但**没说明到什么程度** |
| 关键产出 | 算出「差 1.58 倍」（论文完全没数据） | 算出「整体 34.1% 而非重度组 70.3%」（论文有数据但没加权，且口径未标注） |
| 方法最起作用的部分 | 段 3.5 定量外推 | **分组数据加权还原 + 统计检验密度对比** |
| 适用性 | 论文**缺数据**时，靠外推补出可决策的判断 | 论文**有数据但口径不全**时，靠重算还原 |

这个对照说明一件事：**判读方法要随论文的问题形态调整。** 第一篇的核心是「论文没报，我替你算」；第二篇的核心是「论文报了，但报的是局部，我替你还原整体」。

## 9. 这套方法不适用的情况

诚实说明边界，避免过度推销：

- **纯理论/纯定性论文**：没有可换算的数字，定量外推会退化为空段。
- **扫描件 PDF**：无文本层，提取脚本直接报错退出（退出码 3），需先 OCR。
- **论文本身已经是系统性综述**：综述的结论本就是多层转引，锚点会指向二手表述，「回到原文核查」这一步失去意义。
- **需要复算原始数据的场景**：这套方法只能核对「论文说的是否与原文一致」「换算是否成立」，**无法验证作者的原始计算是否正确**。要验后者必须有原始数据，而多数论文不公开。

最后一条是我这次最想说清的：**这套方法验证的是「引用是否忠实」，不是「论文是否正确」。** 两者都重要，但不是一回事。

### 10.4 需要说明的一处自我修正

我在判读过程中发现，自己的课题文档里写过「骨架化修正可削减约 70% 的弯曲误差」。对照本次判读，**这个表述遗漏了「仅重度弯曲组」这个限定**，按加权还原应为约 32%（整体）。

这不是论文的问题——论文摘要明确写了「for severely curved prawns」，是转引时掉了限定语。我把这条写进分享，因为**它正是这次判读最有价值的实际产出：发现自己已有的一个引用瑕疵**。

### 10.5 一处坐标体系的坑（写验算脚本时踩到）

为了让读者能自己复算，我另写了 `tools/verify_weighted_mape.py`。第一版它按**原样字节**读文件，报出「字符总数 68,654」，而锚点表用的是 **67,438**，两者差 1,216——正好等于文件里 CRLF 的处数。

根因：Python 文本模式读取会把 `\r\n` 折成 `\n`，锚点坐标是在这套折后的坐标上算的；按原样读取则每条锚点都偏移。我取三条已知锚点做了判定：

| 锚点 | 区间 | 原样切片 | 文本模式切片 |
|---|---|---|---|
| 受控实验室条件 | 10119–10167 | 不匹配 | **匹配** |
| 手机 40 cm 俯拍 | 10169–10191 | 不匹配 | **匹配** |
| 保留 300 例 | 36637–36680 | 不匹配 | **匹配** |

所以脚本改成文本模式读取。**这个坑值得单独说，因为它有一个很隐蔽的性质**：如果写入和校验都用同一种方式，会「自己验自己通过」；只有换成另一种方式交叉验证，才会暴露偏移。

顺带一个可复用的判断法：**拿到任何一份带字符区间锚点的材料，先用一条已知锚点在两种读取方式下各切一次，看哪个匹配，再决定后续怎么读。** 不要假定。
